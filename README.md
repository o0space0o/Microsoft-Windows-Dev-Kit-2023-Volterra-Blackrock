# Microsoft Volterra

A private ARM64 Validation OS development image and a space-themed local helper for the Windows Dev Kit 2023. The project belongs to Kevin Thienpont.

The helper configures its workspace automatically. On the installed development OS, the workspace is the OS root. On ordinary Windows, the preview uses this build project. Browser sign-in uses the ChatGPT plan or Codex-managed ChatGPT authentication; GitHub has a separate browser sign-in. No OpenAI API key is required. Account profiles and credentials are excluded from image staging.

Run the preview with `npm start`, then open `http://127.0.0.1:43123/?screen=connections`. Press Ctrl+` to show the live workspace. It supports messages, streamed command output, project history, pause, interrupt, resume, file editing and Codex review. The approved artwork remains byte-identical. Exact pixel comparison passes for all four baseline screens at 1672 × 941; the working panel is a new prototype state and needs separate visual approval.

Say “show services” or “show services matching <text>” in the existing chat to read the local Windows Service Control Manager. The helper reports actual service names, state and startup mode, records the observation in its persistent conversation and labels the OS edition/build that supplied it. Filtering is literal and never enters a PowerShell command. This read-only tool works independently of ChatGPT sign-in and does not start, stop or reconfigure services. PowerShell and policy permission to execute the original collector script are prerequisites; missing APIs or denied script execution are reported as blocked, without changing policy. Host readings do not establish Validation OS or hardware acceptance; target availability still needs a real Validation OS test.

Service inventories require complete rows, distinct identities within the [documented Windows name limits](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-createservicew#parameters) and consistent success/error evidence before any counts are shown. Missing rows, conflicting provider status and collector failures without an Error object produce saved blocked diagnostics. The live checking state clears after those failures, allowing a subsequent valid read.

Say “check TCP <IPv4>:<port>” or “check TCP [<IPv6>]:<port>” to make one [Node TCP connection attempt](https://nodejs.org/api/net.html#socketconnectoptions-connectlistener) to a literal address and port from 1 to 65535. The five-second deadline runs while the event loop can run; late connection events cannot replace a finished result. No application data is sent, no hostname lookup or family fallback occurs, and no network settings change. URLs, credentials, port ranges, scoped IPv6 and caller-supplied socket options are excluded. A transport connection does not verify TLS, HTTP, sign-in, application health, other destinations or target hardware/runtime acceptance; elapsed time includes local setup and scheduling rather than measuring ping latency. The saved chat shows checking without requiring account sign-in. External connectivity and Validation OS testing remain pending.

`node scripts/Check-Source.mjs` checks source boundaries, credential exclusions, locked artwork, JavaScript syntax and the test suite. Tests cover queue persistence, review/check gates, conflict handling, startup rollback, tamper detection, local endpoint authorization, agent interruption/resumption and automatic system workspace selection. `node test/live-codex.mjs` checks actual ChatGPT-backed Codex inference and structured queue outcomes. Image composition uses an isolated ARM64 Windows PE technician VM because this host rejects offline Validation OS registry hives. The technician attaches only its own virtual disks, has no network adapter, and stages the original Microsoft image, runtime packages, verified device-driver catalogs and credential-free helper payload. Firmware update packages are excluded. Servicing receipts are distinct from OS boot, runtime and physical-device acceptance.

`node scripts/Prepare-ImageSource.mjs` prepares a private source snapshot without elevation or image servicing. It requires clean, published main, exports only approved files from that exact Git commit, runs independent source checks and records every file hash. Verification compares the complete manifest with Git objects and published ancestry and reruns the checks. The finalizer consumes this snapshot instead of the live agent's working folder, removes individually identified obsolete source files, rejects destination junctions, verifies source/bootstrap/startup copies and records the same source commit in the image and ISO receipts. Private runtime and vendor OS files remain outside the source reconciliation. ISO creation checks the copied WIM hashes. Development-013 is the single current version. A refresh requires explicit `-BuildName development-013`, a fresh reviewed `-CandidateDirectory`, `-SourceReceipt` and sealed WPF composition authority; a newer application source also requires separate application-overlay authority. Existing current media stays immutable until the candidate is verified and explicitly selected. Legacy build entrypoints and 006-based image creation are retired. Retained 006 receipts, runtime manifests and private recovery WIMs are historical inputs, not current media. Preparing a snapshot does not build, boot or install an OS.

`Test-IsoBoot.ps1 -Phase Inspect` selects the pinned current development-013 media. Prepare and Stop require an explicit `-BuildName`; no previous build is selected implicitly. The read-only `Plan-IsoBoot.mjs` helper checks the selected ISO hash/size, receipt hash and matching image/finalization source commit before Hyper-V is used. VM identities pin these bindings. The test retains generation 2 and Microsoft Windows Secure Boot, rejects unexpected disk/network attachments and does not attach physical disks. Phase completion records the operation performed; OS boot, runtime, recovery and physical-device acceptance each require their own direct evidence. Source fixture tests do not run Hyper-V or refresh media.
