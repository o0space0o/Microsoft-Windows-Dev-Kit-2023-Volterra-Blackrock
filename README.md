# Microsoft Volterra

A private ARM64 Microsoft Validation OS live environment for Kevin Thienpont's Windows Dev Kit 2023, with the approved space-themed overlay and a persistent Codex workspace.

The target is a live RAM boot from the existing A: partition. Windows 11 remains the default boot choice. The overlay and project files live in `Volterra` on the prepared persistent drive; private account profiles and conversation history live separately in `VolterraState`. The user does not need to choose a working folder.

There is one current image, under `build/current`, named `Microsoft Windows Dev Kit 2023 Volterra Blackrock.iso`. There are no numbered releases. An image receipt records its exact source commit, WIM and ISO hashes, and verification status. A created ISO is not evidence of a successful boot or working physical hardware.

The Validation OS base and the overlay have booted in an ARM64 Hyper-V VM. The current refresh removes temporary Chrome setup metrics from the sealed runtime and retries complete private-storage checks during concurrent startup writes. Verification of this refreshed image, A: deployment, native Codex sandbox, guest account sign-in, persistence across restart and physical Dev Kit hardware is still in progress. See the private image and boot receipts for measured status.

ChatGPT and GitHub use separate official browser sign-ins. No OpenAI API key is required. A fresh live environment requires its own initial authorization; host credentials are not copied into the ISO. Once authorized, the helper resumes the saved automatic queue, reports live work in its log and chat, reviews and checks source increments, and publishes successful changes to main. Questions appear in the conversation. Say “pause” or “continue” to control work. Security-sensitive permissions still require an explicit answer.

The four approved reference images remain byte-identical in `design/approved-v1`. The baseline displays use the reference rasters with interactive hit areas. The live log and chat are a working prototype; they are not a complete reconstruction of every custom control. Compare rendered screens at 1672 × 941 before claiming a visual match.

For the Windows development preview, run `npm start` and open `http://127.0.0.1:43123/?screen=connections`. Ctrl+` opens the live workspace. Read-only system queries include “show devices”, “show services”, “show service dependencies”, “show drives”, “show storage”, “show files”, “show networking”, “show DNS”, “show logs”, “show processes”, “show memory”, “show uptime”, “show processors”, “show maintenance” and “check artwork”. Measurements report unavailable APIs and errors rather than implying hardware acceptance.

Run `node scripts/Check-Source.mjs` to check source boundaries, credential exclusions, locked artwork, syntax and the independent test suite. `scripts/Prepare-ImageSource.mjs` exports and verifies an immutable snapshot of clean, published main. `scripts/Build-LiveIso.ps1` refreshes a hash-pinned, already composed private ARM64 Validation OS boot WIM, verifies the source-bound native helper, seals a credential-free persistent seed and builds the UEFI live ISO. It requires administrator rights, the private runtime, Microsoft image tooling, the sealed base WIM/media and their hashes. It refuses to overwrite an existing current image. Earlier numbered-build tooling is historical and does not select this live image.

Helper updates are reviewed and tested in a detached snapshot, pinned by commit and file hashes, and staged for startup. The sealed bootstrap retains prior source and restores an unconfirmed update. Changes to Windows, drivers or firmware need a separately verified offline boot image and recovery path. The helper reports restart requirements; it never restarts the host automatically.
